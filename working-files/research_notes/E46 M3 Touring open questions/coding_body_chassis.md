## 1. Tool setup: BMW Standard Tools, E46 data files, K+DCAN cable, NCS Expert profiles, and the 2026 state on Windows 10/11

### Takeaway
The cleanest current walkthrough is Bali's "Installing BMW Standard Tools" thread on e46fanatics (Dec 2023, 238K views): run `BMW_Standard_Tools_Setup_2.12.0.exe` in compatibility mode, replace the installed folders with a pre-populated `ec-apps.zip` (INPA scripts plus E46 data files), install the FTDI driver, put the cable on COM1 and make `C:\EDIABAS\BIN\obd.ini` match, then confirm two solid black dots in INPA. It works on Windows 7–11, 32- or 64-bit; a May/June 2026 German guide repeats the same steps for Windows 11. For an E46 the K+DCAN cable must have pins 7 and 8 bridged (switch or solder), because only the DME/EGS/SMG are on pin 7 and every body/chassis module (cluster, LCM, DSC) is on pin 8.

**Cable, pins 7/8, COM port and latency**
- Bali: "Older BMWs (like E39, E46) have the DME, EGS, and SMG on pin 7, while all other modules are on pin 8. Newer BMW models have all modules on pin 7. The switch connects or disconnects pins 7 and 8 … If your cable has no switch, soldering together the circuit board pads for pins 7 and 8 will put it in the older configuration to make it work on your E46." — [e46fanatics: Installing BMW Standard Tools](https://www.e46fanatics.com/threads/installing-bmw-standard-tools.1322014/) [read]
- MS4X wiki: "verify that pin 7 and 8 on the OBD side of the cable are shorted together, some cables provide an external switch … If no switch is present, then pin 7 and 8 needs to be soldered together", because "on the newer E90 platform pin 7 is used for K-Line and pin 8 was reassigned for ethernet … On the older platforms pin 7 and 8 are both used for K-Line" — [MS4X Wiki: How to connect](https://www.ms4x.net/index.php?title=How_to_connect) [read]
- Real symptom (Feb 2025): an M3 owner could talk to DME and SMG but not the light module or cluster, so NCS Expert could not read the vehicle order; "My cable did not have pins 7 or 8 jumpered, so I soldered them together. Now I can talk to all modules in INPA and was able to get the vehicle order." — [NAM3: Verify NCSExpert function before doing manual swap](https://nam3forum.com/forums/forum/main-forum/e46-2001-2006/293965-verify-ncsexpert-function-before-doing-manual-swap) [read]

### Inferences
- For this car, budget a dedicated used Windows 10/11 laptop running natively (not a VM), a switched K+DCAN with genuine FTDI chip (switch set to "pins 7+8 bridged"), and a separate PA-Soft/BMW Scanner 1.4 interface for cluster/LCM EEPROM work; on Windows 10/11 the PA-Soft driver install is the step most likely to fail (Bali), so install it before you depend on it.
- Before touching any module, prove the setup on the unmodified Touring: INPA must show two black dots and read KMB/EWS (pre-09/2001) or AKMB/ALSZ (09/2001+) and the DSC; NCS Expert must read the ZCS/FA. Failure to read the cluster/LCM almost always means pins 7/8 or the COM port.
- Latency: start at 1 ms for INPA/NCS (most guides); if a specific flasher wants 16 ms, change it for that session.

### Gaps
- No authoritative statement of the final SP-Daten release that covers the E46, or of which NCS Expert build (3.x vs 4.x) is safest on Windows 11; reports conflict (v3.0x vs v4.x, single forum claim).
- The "gushmazuko/bmw-advanced-tools" GitHub package could not be verified (GitHub access blocked in this environment).
- BMW's own EDIABAS INI documentation (an `INI.pdf` mirror) could not be fetched (connection reset); the `STD:OBD` default rests on secondary sources.
- Standard Tools, INPA scripts, SP-Daten and Revtor's profile are BMW-internal or community-modified files circulated through forums and vendors; no official download exists, and I did not verify any download source.

## 2. Coding concepts: ZCS versus FA, reading and editing the vehicle order, and making M3 modules accept a 325i Touring's data

### Takeaway
E46s built before 09/2001 carry a ZCS (GM/SA/VN hex strings) stored in the cluster (KMB) with a backup in the EWS; from 09/2001 they carry an FA/vehicle order stored in the cluster (AKMB) with a backup in the light module (ALSZ). NCS Expert codes every module from that key plus the module's coding index; the key's type code determines body (TOUR/LIM/COUP), engine (M54B25 vs S54B32) and market, and the production date (#MMYY) determines which module versions NCS will accept. M3 modules are made to accept the car either by editing the FA (option codes, production date, possibly type code) or by leaving the default coding alone and editing individual parameters in FSW_PSW.MAN.

### Cited Findings
- FA cars (09/2001+): "The instrument cluster (AKMB) stores the car's FA (central coding key) … The light control module (ALSZ) also stores the FA as a backup copy in case the cluster gets replaced." ZCS cars (before 09/2001): "The instrument cluster stores the car's ZCS … The EWS also stores the ZCS as a backup" — [Bali FA DIY](https://www.e46fanatics.com/threads/diy-how-to-code-fa-for-at-mt-swap.1290835/) [read], [Bali ZCS DIY](https://www.e46fanatics.com/threads/diy-how-to-code-zcs-for-at-mt-swap.1290589/) [read]. Same split: "For ZCS cars this is stored in the EWS and the KOMBI (cluster), and for FA cars this is stored in the LSZ (light switch) or the KOMBI" — [NAM3: MK60 swap coding](https://nam3forum.com/forums/forum/special-interests/coding-tuning/232995-mk60-swap-coding) [read]
- Reading the FA (verbatim clicks, Bali): Start NCS Expert → **File, Load Profile** → **Expert Mode** → OK → **VIN/ZCS/FA** → **ZCS/FA f. ECU** → **E46** → OK → **AKMB** → OK; "NCS Expert reads the FA from the module you selected" — [Bali FA DIY](https://www.e46fanatics.com/threads/diy-how-to-code-fa-for-at-mt-swap.1290835/) [read]. ECUWorx: "there will be a list of 4 modules to read the VO from – pick either AKMB or ALSZ, doesn't matter which … you should see the 'FG' and 'FA' fields populate" — [ECUWorx M-Track PDF](https://www.ecuworx.co.uk/uploads/M-Track.pdf) [read]
- Editing and writing the FA (Bali): **Enter FA** → **E46** → OK → OK "leaving the VIN value unchanged (the VIN characters won't match exactly)" → select an option code in the list and press **Delete** (or type a new one under Attribute and **Add**) → OK → **Back** → **Process ECU** → **AKMB** → OK → **Change Job** → **FA_WRITE** → OK → **Execute job** (status goes "Job active" → "Job ended") → **Change ECU** → **ALSZ** → **Execute job**. Then reload with the **Factory Coding** profile, read the FA back, **Process Car** → **Code Car**; "The Code Car function fails out on the first module coding failure. In this case just code the rest of the modules singly." Afterwards reset DME adaptations so the DME picks up the new FA — [Bali FA DIY](https://www.e46fanatics.com/threads/diy-how-to-code-fa-for-at-mt-swap.1290835/) [read]
- Editing a ZCS (Bali): **Enter ZCS** → E46 → OK → OK; three hex fields **GM**, **SA**, **VN**; "Remove the last digit from all 3 fields (they are checksum values)", tick **Calculate checksum**, change the relevant bit (for AT→MT: "Clear bit 3 (subtract 8) in the last digit of the SA string"), **Process ECU** → **KMB** → **Change Job** → **ZCS_SCHREIBEN** (Bali's text also spells it "ZCS_SCHRIEBEN") → **Execute job** → **Change ECU** → **EWS** → **Execute job**; then Factory Coding profile → Process Car → Code Car — [Bali ZCS DIY](https://www.e46fanatics.com/threads/diy-how-to-code-zcs-for-at-mt-swap.1290589/) [read]
- What the type code means: in `E46ZST.000`, the 2001 330i sedan's type line is `AV53 65630000 0000204004201000 0000000000 1 LIM M54B30 LL US //Limousine 330i US 06/00 - 08/01`, i.e. the type code maps to body (LIM), engine (M54B30), left-hand drive and US market; option lines look like `H MK60 N1099 … 1 MK60 // alle Fzg mit ASC oder DSC MK60` and `H LEN1 N0301 … 1 LENK_I_50 //(LIM,COUP,TOUR,CABR)+(M54B30,M57D30,M56B30)+SA210 ab 04/01`. You can hand-build a ZCS containing only the options relevant to the module you are coding — [e46fanatics: MK60 coding index thread (TerraPhantm)](https://www.e46fanatics.com/threads/mk60-coding-index-the-following-control-unit-is-not-allowed-for-this-coding-job.1264623/) [read]
- The MK60 coding rules key off exactly those keywords: liam821's dump of `E46.MK60.C12` lists conditions such as `S54B32`, `!S54B32`, `TOUR`, `CABR`, `LIM`, `COUP`, `M54B25`, `M_TRACK_MODE`, `CSL`, `RDW`, `MK60_CI_09`, `MK60_CI_12` for each parameter (e.g. `DRUCKMODELL_HINTERACHSE` has a branch for `(TOUR,CABR)+!S54B32`; `MOTOR_ART_DSC_2` values include `m52b25`, `m54b25`, `m54b30`, `s54b32`) — [liam821: MK60 comparison PDF](https://liam821.com/MK60-Comparison.pdf) [read]

### Inferences
- First job of the whole electrical phase: with the Touring's original cluster, LCM and DSC still fitted, read and save its ZCS or FA (screenshot the option list, production date and type code) and READ ECU / save `FSW_PSW.TRC` and `NETTODAT.TRC` for KMB/AKMB, LSZ/ALSZ, GM5, DSC, EWS and IHKA. Everything later depends on that record.
- Do not write an M3 type code into the Touring's stored FA (AKMB/ALSZ): body-dependent modules (GM5 tailgate/rear wiper, LCM Touring lamps) would then default-code as a coupe. If a type-code change is used at all, do it only in the NCS session used to code the DSC (and possibly the cluster), without FA_WRITE. This is my reading of how the type code drives the rules above; no swapper documented doing it on a Touring.
- A pre-09/2001 (ZCS) Touring receiving a post-09/2001 M3 cluster (AKMB) is the hardest case: the cluster expects an FA that the car's KMB/EWS world doesn't hold. The two documented ways out are (a) convert the car to FA by fitting a newer LCM and writing an FA to LCM and cluster, or (b) build an FA manually in NCS for coding sessions.

### Gaps
- I could not find the FA-side equivalent of `E46ZST.000` (the type-code table for FA cars) or the US type codes for the 325iT and US M3 coupe; check them in your own `C:\NCSEXPER\DATEN\E46` files.
- No source documents converting a ZCS Touring to FA step by step in English.
- Exact meaning of `$7MA` was not confirmed (it is the code ECUWorx adds to enable M Track; I could not verify that it is the ZCP option code).

## 3. M3 instrument cluster (KOMBI/AKMB) in the Touring: EEPROM backup, VIN, mileage, coding index, options, speedometer and tamper dot

### Takeaway
The proven route is: back up the M3 cluster's EEPROM with PA-Soft, produce a "virgin" image (odometer bytes zeroed, VIN set to the Touring's last seven characters) and write it onto a fresh M35080 EEPROM (desoldering the original, or soldering in a blank chip and writing the image with PA-Soft), then fit the cluster: with matching VIN it takes the true mileage from the light module and the tamper dot stays off. Then fix individual options (oil level, M Track light) in NCS Expert by editing FSW_PSW.MAN rather than default-coding the cluster. One S54 wagon owner documented exactly this sequence (24H M3 cluster, blank chip, PA-Soft); a second S54 wagon ran an M3 cluster with matching VINs. Legally, the result must show the Touring's true mileage.

**EEPROM facts**
- Chip: "93C66 for Motormeter clusters, and M35080 for Bosch clusters"; later clusters use "m35080v6", earlier "m35080 3"; "the v6 chip cannot be written by a box-stock r270 programmer" but can be read, and its image can be written to a "3" chip — [e46fanatics: DIY M3 Cluster into Non-M](https://www.e46fanatics.com/threads/diy-m3-cluster-into-non-m-retrofit.1277945/) [read]

### Inferences
- Recommended order for this car (synthesis of the reports above, not a single source): (1) record the Touring's true odometer reading (photo) and save PA-Soft backups of the old cluster and the LCM; (2) with the M3 cluster plugged in, read its EEPROM in PA-Soft and keep the untouched file; (3) make a copy with bytes 0x00–0x1F zeroed and the VIN at 0x7A–0x7E set to the Touring's last seven VIN characters; (4) write it to a new M35080 (programmer) or solder in a blank chip and write it with PA-Soft; (5) fit the cluster, switch on, confirm the true mileage appears from the LCM and no tamper dot; (6) only then change options via FSW_PSW.MAN. Never write a mileage into the LCM from a donor cluster: the LCM holds the car's true record.
- Keep the M3 coding index (23/24 preferred) for an S54 car. Changing it to non-M CI 08 (as the non-M retrofit DIYs do) would let NCS apply non-M gauge definitions, which is the opposite of what an S54 needs; the 9,000 rpm stuck-tach case shows how badly a default coding can go on a modified cluster. Prefer FSW_PSW.MAN edits of named parameters on the donor's existing M3 coding.
- Correction for the existing guide: its statement that the DIY's 8.9% speedometer error "came from that car's non-M diff" is not supported. The M3 cluster's own `TACHO_VOR_KENNLINIE` (49/45) builds in an ~8.9% over-read versus ~5.7% for non-M clusters, so the same over-read will appear in the Touring as in a stock M3. Check against GPS; if you want true speed, the documented fix is the EEPROM edit of that 7-byte table (keep the original BIN).
- The non-M DIY's other mileage method (raise the cluster's coding access by changing CI 24→08 at offset 0x317, set the tire-scaling value from 4797 to 1 so the odometer runs up ~8,000 miles per mile driven, then set it back) only moves the reading forward but is imprecise ("1-10 +- is completely fine" per the author) and means driving with a meaningless speedometer — [e46fanatics DIY, first post](https://www.e46fanatics.com/threads/diy-m3-cluster-into-non-m-retrofit.1277945/) [read]. Not recommended; the virgin-EEPROM route sets the true mileage exactly.
- A 2001–early-2002 M3 cluster (CI 20/21, "Motometer" group per KamilFKH) might be programmable entirely in PA-Soft like the 323Ci case above; the 2003-on CI 23/24 Bosch clusters need the M35080 route. This pairing of two sources is my inference; check the board maker before buying tools.
- Pick a redesign M3 cluster (CI 23/24, roughly 2003-on) if possible: M Track light and brake-force display support, and (for a 09/2002+ Touring) no backlight wire to add.

## 4. Light module (LCM/LSZ) and general module (GM5): coding after the swap and the order of operations

### Takeaway
Neither module needs swap-specific coding when you keep them: the LCM is the master copy of VIN and mileage (and, on 09/2001+ cars, the FA backup), so the cluster is made to match it, never the reverse. Re-code LCM/GM5 only if you change the FA. GM5's stored VIN is irrelevant.

### Cited Findings
- The ALSZ holds the FA "as a backup copy in case the cluster gets replaced"; Bali writes the modified FA to AKMB then ALSZ, and says that after an FA change "Only a few modules beyond AKMB (cluster) and ALSZ (lighting) need coding … ABS/ASC/DSC, LCM, and maybe GM5, IHKA" — [Bali FA DIY](https://www.e46fanatics.com/threads/diy-how-to-code-fa-for-at-mt-swap.1290835/) [read]
- Order used by a 330Ci owner (Jun 2020): EEPROM erased and resoldered → "Used PASoft to set the VIN of my car. After that was done my cluster automatically took my mileage from the LCM" — [e46fanatics: E46 M3 cluster coding, post #17](https://www.e46fanatics.com/threads/e46-m3-cluster-coding.1278842/) [read]
- LCM can be written with PA-Soft: "Using PASoft; Click (Reprogramming) -> Write Odometer -> … Next; Click (Write FGSTNR) Put last 7 Numbers of VIN" (the DIY uses this to make the LCM match the donor cluster, which would change the car's recorded mileage) — [e46fanatics DIY, first post](https://www.e46fanatics.com/threads/diy-m3-cluster-into-non-m-retrofit.1277945/) [read]
- Mileage relation between modules: "either the mileage has to match 100%, or the mileage on the lcm has to be set to zero. It will eventually adapt" (hearsay in the post) — [NAM3: Cluster Replacement](https://nam3forum.com/forums/forum/main-forum/e46-2001-2006/228697-cluster-replacement) [read]
- GM5: "the module needs to be reset to defaults based on the VO"; coding a used GM5 = write a blank .man; "the VIN on the GM5 doesn't actually impact anything"; a COAPI-2060 write failure was a slightly loose pin in the GM5 harness connector — [NAM3: NCS error recoding used GM5](https://nam3forum.com/forums/forum/special-interests/coding-tuning/21981-ncs-error-while-trying-to-recode-used-gm5-module) [read]

### Inferences
- Legal and practical rule for this build: treat the Touring's LCM as the source of truth. Do not use the DIY's "write odometer to LCM" step with a donor cluster's reading; that changes the car's mileage record (49 U.S.C. §32704 territory). Make the cluster match the LCM instead.
- Order of operations that avoids mismatches: back up LCM and old cluster → fit the virgin M3 cluster (VIN = car) → let it read mileage from LCM → (FA cars) confirm AKMB holds the car's FA, FA_WRITE from the saved FA if not → code DSC → initialise DSC VIN/steering angle → clear all faults → only then change any option codes. DSC VIN faults clear once cluster VIN and DSC VIN match the car (see section 5).

### Gaps
- No source documents any LCM coding parameter that depends on the engine or cluster type for an S54 swap. No GM5 change is needed for the swap according to everything I found, but nobody wrote that explicitly for a Touring.

## 5. M3 DSC (MK20/MK60) in a 325i Touring: which unit, coding, VIN, INPA/Tool32 calibration and bleeding

### Takeaway
The DSC is the least predictable part. Documented S54 wagons split: one ran fine on both the Touring's own non-M MK60 and an M3 MK60; another could not clear "VIN not initialized" with an M3 MK60 and fixed it by refitting the 325i unit. NCS codes the MK60 from one shared data file whose rules choose M3 values only when the FA says `S54B32`; a 325i Touring FA says `M54B25`/`TOUR`, so an M3 unit default-coded from the Touring's FA gets 325i values unless you intervene (FA edit for the session, or manual FSW_PSW.MAN values). After any coding: initialise VIN and steering angle (INPA MK60 Shift+F4 → F1, or Tool32 `DSC_MK60.PRG` → `lenkwinkel_dsc_abgleichen`), run the compensation routines, clear faults, and bleed with the INPA pump routine.

### Inferences
- Decision for this build: Option A, keep the Touring's own MK60 (needs no FA tricks and was the fix in wagon #1); optionally raise its parameters toward M3 values with NCS Dummy, accepting that you are hand-tuning a safety system. Option B, the M3 MK60 (Bry5on's wagon proves it can work): it must get M3 values, which a 325i FA will not produce by default because the C12 rules select S54 values only on `S54B32`. Either code it in a session using an FA whose type code yields `S54B32` (without FA_WRITE), or default-code and then set the M3 STD column values from liam821's table via FSW_PSW.MAN (`MOTOR_ART_DSC_2 = s54b32`, `LENKWINKELKENNLINIE_2 = wert_05` for the standard M3 rack, `DRUCKMODELL_*` for the brakes actually fitted, `BAUART_MK60 = coupe_m` since no M3 Touring variant exists). Both branches are my synthesis; no source documents an M3 MK60 coded into a Touring step by step.
- A pre-09/2001 Touring has the early MK60 with analog yaw/lateral sensors; an M3 MK60 (09/2002+ design) expects the CAN sensor cluster, so fitting it there also means the later sensor cluster and its wiring (blarf's notes). A 09/2001+ Touring already has the CAN sensor cluster.
- If NCS doesn't list "MK60" or rejects the coding index, check the FA production date first (`#0902` or later for an M3 MK60), then the coding index of the unit (BMW Scanner shows "CI" in its header).
- The DSC VIN fault (5E1F/5EF1, reported under both numbers) is expected after any module swap; it clears when cluster VIN = car VIN and the INPA/Tool32 initialisation runs. Do the cluster VIN first, then DSC coding, then initialisation.
- Brake safety: road-test only after a firm pedal, then confirm ABS works (cautious hard stop on a quiet road) and re-bleed after a few drives. Do the INPA pump routine with a firm pedal, not a light 80 %.
- Steering-angle sensor access: BMW's DSC III training places the sensor "at the bottom of the steering column near the flexible coupling" (E38/E39 document) — [BMW DSC III training](https://www.ge39.com/files/DSC.pdf) [read]; an E46 owner planned to "do my steering giubo while I'm in there" when replacing his — [e46fanatics: Calibrating Steering Angle With INPA](https://www.e46fanatics.com/threads/calibrating-steering-angle-with-inpa.1287151/) [read]. So SAS work shouldn't need the airbag disturbed; anything at the wheel itself (MFL buttons, an M3 wheel) does, and needs the battery disconnected and BMW's airbag precautions (general caution, no E46-specific source found here).

## 6. Other modules the swap may touch: IHKA/IHKR, MFL and cruise, PDC, EWS clutch/park-neutral input, steering-angle sensor

### Takeaway
Little coding is reported beyond cluster and DSC. Cruise control in one S54 wagon needed the M3 clutch switch module (hardware); A/C was reported working with the S54 on automatic-climate cars; nothing was found for PDC. The EWS clutch/park-neutral input is the EWS parameter `PARK/NEUTRAL_EINGANG` (NCS Expert; also settable in BMW Scanner 1.4), which should stay `aktiv` on this US manual car; it matters only if the EWS is swapped or was SMG/auto-coded. A swapped steering-angle sensor must be coded with NCS before Tool32 can calibrate it.

## 7. ISTA and dealer-only jobs versus generic tools

### Takeaway
None of the body/chassis jobs strictly needs ISTA: NCS Expert, INPA/Tool32, PA-Soft and an EEPROM programmer cover them. ISTA/dealer help is relevant for a brand-new (virgin) cluster from BMW and offers guided DSC bleeding and steering-angle adjustment. Generic tools cannot do this E46 work: BimmerGeeks ProTool explicitly excludes E46 coding, Carly lists only comfort/lighting coding, and the Foxwell NT530 offers resets (steering angle, brake-bleed mode) but not module coding.

### Cited Findings
- ProTool: "Diagnostic Support: All OBD2 BMW, Mini or Rolls Royce models. Coding Support: Most BMW … Models EXCEPT older chassis (Gen 1) such as E46, E39, E38, E53, E85 and anything older" — [BimmerGeeks ProTool](https://www.bimmergeeks.net/protool) [read]
- Carly E46 coding areas: alarm, brake lights, cleaning, comfort, coming home, convertible, DRL, easy entry, flash to pass, headlamp cleaning, high beam, interior lights, locking, mirrors, opening, power windows, side marker, tailgate/rear door, turn signals, voltage monitoring, key programming; no DSC, cluster VIN or mileage functions listed — [Carly blog: BMW E46 coding list](https://www.mycarly.com/blog/car-coding/bmw-e46-coding-list-what-you-can-code/) [read; vendor page]
- Foxwell NT530 (BimmerWorld listing): reads/clears ABS/DSC and body codes, "steering angle sensor reset", "brake bleeding mode*" (asterisked as model-dependent), but "This tool does not support all / broad control module coding and programming. For those dealer-level coding tasks, you really need dealer type tools (like ISTA, Rheingold, NCSexpert, etc)"; pre-2001 cars may need a 20-pin adapter — [BimmerWorld: Foxwell NT530](https://www.bimmerworld.com/Tools/Foxwell-NT530-OBD-System-Scanner-for-BMWs.html) [read; vendor page].
